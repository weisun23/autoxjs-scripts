# 汽水音乐 · 自动领会员

自动观看汽水音乐 **「我的 → 继续领」** 的激励视频，逐日解锁畅听时长 / 会员。

> [!WARNING]
> 仅供学习交流。本脚本模拟人工点击，可能违反汽水音乐的用户协议，账号风控风险自负。
> 建议不要长时间挂机（脚本默认上限 30 条 / 60 分钟就是为了这个）。

- **文件**：[`汽水音乐-自动领会员.js`](汽水音乐-自动领会员.js)
- **测试环境**：小米 M2102J2SC（Android 11 / MIUI 12.5），汽水音乐 21.1.0，AutoX.js v7
- **前置条件**：见 [环境准备](../../docs/环境准备.md)，**无障碍服务必须开启**

## 使用方法

1. 确认无障碍服务已开（[环境准备](../../docs/环境准备.md)）
2. 把 `汽水音乐-自动领会员.js` 放进手机脚本目录（一般是 `/sdcard/脚本/`）
3. 打开汽水音乐并**登录账号**
4. 在 AutoX.js 里运行脚本 —— 不用手动切到「我的」页，脚本会自己导航过去

## 怎么停

| 方式 | 效果 |
| --- | --- |
| **按音量上键或音量下键** | ✅ 立刻停，走完收尾流程后打印运行统计 |
| **连续 2 次离开汽水音乐**（按 HOME / 切到别的 App） | ✅ 脚本判定为用户主动退出，自行结束 |
| 在广告里按返回键 | ❌ 没用。脚本会点「继续观看」把你的返回撤销 |
| 在「我的」页按返回键 | ❌ 没用。脚本会重新导航回来继续 |
| 强杀 AutoX.js 进程 | ✅ 停，但**会导致无障碍开关被 MIUI 自动关掉**，下次要重新开 |

结束时会打印统计，`盲点兜底` 是判断脚本在你机型上健康度的关键指标：

```

结束原因：达到配置上限
观看广告：30 条（上限 30）
运行时长：15.2 分钟（上限 60）
盲点兜底：0 次          ← 正常应接近 0，偏高说明该机型的选择器需要补充
异常恢复：0 次
==============================
```

## 配置项

改脚本顶部（第 29 行附近）的 `LOCAL_ENV`：

```javascript
var LOCAL_ENV = {
    maxAdWaitSec: '',       // 单条广告最长等待（秒），默认 90，范围 20-300
    maxRunMinutes: '',      // 总运行时长上限（分钟），默认 60，范围 1-480
    maxAdCount: '',         // 最多观看广告条数，默认 30，范围 1-200
    selftest: ''            // 填 '1' 只跑内置自检，不操作界面
};
```

留空表示用内置默认值。填数字要**加引号**（会按整数解析，超范围会自动钳制并打警告）。

**自检模式**：把 `selftest` 改成 `'1'` 运行，脚本只跑纯函数断言，完全不动界面，
用来确认改动没把状态机改坏：

```
========== 自检开始 ==========
[状态判定优先级]
  ✓ 中断弹窗优先于播放中
  ✓ 奖励弹窗优先于领取成功
  ...
========== 自检结束：通过 58，失败 0 ==========
```

## 工作原理

单层状态轮询：每轮采集一次界面上下文 → 判定状态 → **只执行一个动作** → 重新判定。
没有嵌套循环，所以不存在「进了广告就出不来」的结构性风险。

状态优先级（顺序不可调换，注释里写了原因）：

| 状态 | 触发信号 | 动作 |
| --- | --- | --- |
| `INTERRUPT_DIALOG` | 「继续观看」 | 点「继续观看」救回广告 |
| `REWARD_DIALOG` | 「领取奖励」 | 计数 + 点「领取奖励」加载下一条 |
| `AD_DONE` | 顶栏 desc 变为「领取成功，关闭，按钮」 | 点顶栏关闭按钮 |
| `SHEET_DIALOG` | 「第N天畅听」+「再看N个提前领」 | 点右上角 ✕ 关掉 |
| `LIVE_PAGE` | 「更多直播」 | `back()` |
| `AD_PLAYING` | 当前 Activity 含 `ExcitingVideoActivity` | 读倒计时，归零前不动 |
| `TASK_ENTRY` | 「继续领」/「领时长」 | 点任务入口 |
| `OFF_TRACK` | 前台包名不是汽水音乐 | `back()` ×2，无效则重启 App |
| `UNKNOWN` | 都不匹配 | 累计 15 轮后 `back()`，再 15 轮重启 App |

### 几个从真机测试里挖出来的关键点

这些是实现细节，但都踩过坑，写下来方便 App 更新后修：

**1. 用顶栏倒计时精确等待，不盲等固定秒数**

穿山甲 SDK 把剩余秒数写在顶栏按钮的 `contentDescription` 里：

```
"13秒后可领取奖励，关闭，按钮"     ← 播放中
"领取成功，关闭，按钮"            ← 倒计时归零
```

脚本逐秒跟读，归零后文案翻转才动作。既不会点早（会弹中断窗），也不白等。

**2. `descMatches` 是整串匹配，不是子串匹配**

真机实测：

```javascript
descMatches(/\d+秒后可领取奖励/)     // false  ← 实际文案后面还有「，关闭，按钮」
descMatches(/\d+秒后可领取奖励.*/)   // true
```

所以凡是匹配「前缀固定、后面还有文案」的控件，正则尾部一律要加 `.*`。

**3. 广告顶栏按钮的 bounds 高度会塌缩成 0**

实测报出来是 `[619,91,1036,91]`，直接取中心会点进状态栏。
所以点击位置从塌缩的 `top` 往下偏移 40px（`CONFIG.topBarClickOffsetY`）。

**4. WebView 渲染的按钮吃 `click()` 不吃 `press()`**

奖励弹窗是 WebView 渲染的，同一个坐标 `press()` 无效、`click()` 生效。

**5. 会员成长弹窗的按钮在无障碍树里完全不可达**

弹窗期间 `currentActivity()` 返回的是 `android.app.Dialog`、`currentPackage()` 返回
`miui.systemui.plugin`，和真实 Activity 对不上；整个弹窗 `text 节点共 0`。

所以脚本改用 contentDescription 判定它，并且**只点右上角 ✕ 关掉**，
走已验证的「继续领」入口推进——**刻意不点「解锁第N天畅听」**，
因为那个措辞无法排除是付费入口。

**6. 一次「离开 App」只算一次跑偏**

跑偏期间每轮轮询都会走到恢复逻辑，如果每轮都计数，**按一次 HOME 会被算成 3 次**。
脚本用 `offTrackEpisodeCounted` 标志保证一次连续跑偏只计一次。

## 已知限制

- **必须前台运行**，熄屏或切走就取不到控件
- **顶栏点击坐标按屏幕比例算**（`0.907W, 0.555H`），我是在 1080×2340 上测的。
  其他分辨率理论上会按比例缩放，但没有实测
- **不理会「解锁第N天畅听」**：按钮语义不明（可能是付费），脚本选择关掉弹窗走「继续领」。
  畅听天数照样涨，只是不走那条捷径
- **只有 v2/v3 签名之类的跟本脚本无关**，忽略

## 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动就报 `无障碍服务未启动` | 无障碍没开 | 见 [环境准备](../../docs/环境准备.md) |
| 日志里 `未能获取 汽水音乐 包名` | Android 11 包可见性限制 | 脚本会自动回退到内置包名常量，不影响使用 |
| 一直 `UNKNOWN` 打转 | 汽水音乐版本更新，界面变了 | 提 Issue 并附日志 |
| `盲点兜底` 次数比广告条数还多 | 该机型选择器命中率低 | 提 Issue 并附日志，一般是文案或坐标差异 |
| 卡在广告页不动 | 该广告没暴露倒计时节点，走了盲等回退 | 属正常，到 `maxAdWaitSec` 会强制关闭 |
| 脚本把 App 拉不起来 | 缺「后台弹出界面」权限 | 见 [环境准备](../../docs/环境准备.md) 第 3 节 |
